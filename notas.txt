Sí, ese flujo es totalmente viable. El proceso seguro sería:

  1. Copia que te envía el cliente

  - Pídele que ejecute el botón “Descargar respaldo (.sqlite)” o copie manualmente data/clinic.sqlite y te envíe ese archivo.
  - Confirma que proviene de su commit actual (cc9a532…) y guárdalo con un nombre que identifique la fecha/cliente, p. ej.
    clinic_cliente_20251112.sqlite.

  2. Actualiza la estructura tú mismo

  - Trabaja sobre una copia, nunca sobre el archivo original recibido.
  - Desde tu terminal:

    sqlite3 clinic_cliente_20251112.sqlite "ALTER TABLE clinical_profiles ADD COLUMN consent_signature TEXT;"
    sqlite3 clinic_cliente_20251112.sqlite "ALTER TABLE clinical_profiles ADD COLUMN consent_ci TEXT;"
  - Repite para cualquier otro cambio de esquema posterior (revisa commits por más columnas nuevas).
  - Verifica que la estructura quedó correcta: sqlite3 clinic_cliente_20251112.sqlite ".schema clinical_profiles" y asegúrate de que los datos
    siguen ahí (SELECT COUNT(*) FROM patients;).
  - Opcional: ejecuta VACUUM; para compactar antes de enviarla de vuelta.

  3. Se la devuelves al cliente

  - Indícale que primero respalde su archivo actual (por ejemplo copiándolo a backups/clinic_pre_actualizacion.sqlite).
  - Luego que sobrescriba data/clinic.sqlite con el que le enviaste y abra la app para confirmar que todos los pacientes/datos aparecen y las
    vistas nuevas (firma) funcionan.

  4. Limpieza en Git

  - Una vez verificado que todo corre con la base migrada, sí:

    git rm --cached data/clinic.sqlite
    git commit -m "Dejar de versionar base local"
    git pull --rebase origin andrea
    Con eso, data/clinic.sqlite deja de formar parte del repositorio, así que futuros git pull no tocarán la base; solo necesitará correr
    migraciones cuando haya cambios de esquema.

  Si prefieres automatizar el paso 2, puedes usar el script scripts/update_client.ps1 que ya creamos: ejecútalo apuntando al archivo que te
  envió (.\scripts\update_client.ps1 -DatabasePath .\clinic_cliente_20251112.sqlite -SkipGitPull). Este detecta si las columnas existen antes de
  aplicar los ALTER, así evitas errores si vuelves a ejecutarlo.

  Avísame si quieres que prepare un fichero .sql con todas las migraciones acumuladas para enviárselo junto a las instrucciones.
